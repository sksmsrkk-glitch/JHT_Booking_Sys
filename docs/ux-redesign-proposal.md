- 작성일: 2026-07-19
- 기준 디자인: `DESIGN-notion.md` (Notion 디자인 언어)

- 목적: ① Notion 디자인 언어로 전면 이관 ② 어드민·파트너 워크플로우를 더 빠르고 덜 헷갈리게

## 0. 12세도 이해하는 한 줄 요약

> 지금 시스템은 **방이 35개인데 지도가 없는 학교**입니다.
> 여행 한 팀을 처리하려면 6개 방을 돌아다녀야 합니다.
> 제안: **피자 트래커처럼 한 화면에서 진행 상황을 보고 바로 처리**하게 만들고,
> 벽 색깔은 **차가운 회색 → 따뜻한 종이색(Notion)** 으로 바꿉니다.

## 1. 현재 시스템 구조 (파악 결과)

### 1-1. 여행 한 팀이 지나가는 길 (라이프사이클)

```
파트너 문의        →  견적 작성      →  견적 발송   →  파트너 수락
(agency_inquiries)   (quote_cases)     (sent)        (accepted)
        ↓
    예약 생성      →  운영 업무 배정  →  공급사 연락  →  확정서 작성
   (reservations)    (operation_tasks)  (supplier_msg)  (final_snapshot)
        ↓
    인보이스 발행  →  입금 확인      →  정산 승인
    (invoices)       (payments)        (settlements)
```

**중요 발견:** `workflow_threads` 테이블이 이미 이 전부를 하나로 묶고 있습니다.

| 컬럼 | 연결 대상 |
|---|---|
| `workflow_code` | 투어 코드 (예: `MY-WORLDTRAVE-20260627-A1B2C3`) — 유일값 |
| `agency_account_id` | 어느 파트너 |
| `agency_inquiry_id` | 원래 문의 |
| `quote_case_id` | 견적 |
| `reservation_id` | 예약 |
| `current_invoice_id` | 인보이스 |

→ **척추(spine)는 이미 있는데, 지금은 "메시지 대화" 기능에만 쓰이고 있습니다.**
→ 이 위에 "단체 상황판"을 올리면 **새 테이블 없이** 가장 큰 개선이 가능합니다.

## 2. 디자인 이관 제안 (Notion 언어)

### 2-1. 왜 Notion이 이 시스템에 잘 맞는가

Notion 디자인은 **"문서 같은 차분함 + 밀도 높은 데이터"** 를 위해 만들어졌습니다.
여행사 운영툴이 정확히 그런 도구입니다. 실제로 현재 코드에도 이미
`partner-database-shell`, "Notion-style board" 같은 이름이 쓰이고 있어 방향이 일치합니다.

### 2-2. 토큰 교체표 (1단계 — 이것만 바꿔도 60% 완성)

| 토큰 | 현재 | Notion | 효과 |
|---|---|---|---|
| 페이지 배경 | `#f2f4f6` | `#f6f5f4` | 차가운 회색 → 따뜻한 종이 |
| 카드 표면 | `#ffffff` | `#ffffff` | 동일 |
| 주요 색 | `#3182f6` | `#0075de` | 버튼·링크 전용 |
| 주요 색(눌림) | `#1b64da` | `#005bab` | |
| 본문 글자 | `#191f28` | `#000000` (95% 알파) | 더 또렷 |
| 보조 글자 | `#4e5968` | `#31302e` | 따뜻한 회색 |
| 흐린 글자 | `#8b95a1` | `#615d59` / `#a39e98` | |
| 실선 | `#e5e8eb` | `#e6e6e6` | |
| 모서리 | 10/14/18/24 | **4/5/8/12/16** | 더 단정하고 밀도 있게 |
| 그림자 | `0 8px 24px 8%` 1겹 | 반투명 **4겹** 레이어 | 종이 위에 살짝 뜬 느낌 |

### 2-3. 폰트 (한국어 문제 — 결정 필요)

Notion 규격은 **Inter 단독**입니다. 그런데 어드민은 한국어를 씁니다.

**제안:**
- 파트너 포털(영어 전용): `Inter` 순정 → Notion 그대로
- 어드민(한/영 혼용): `Inter, Pretendard, ...` — 숫자·영문은 Inter가, 한글은 Pretendard가 렌더
- 제목에 Notion의 **음수 자간**을 명시 적용 (40px 제목이면 `-1px`)

### 2-4. 색상 규칙 (Notion의 핵심 규율)

```
✅ 파랑(#0075de) = 오직 "주요 버튼 + 링크 + 선택됨" 에만
✅ 스티커 색(보라·핑크·주황·청록·초록) = 장식/카테고리 점 에만
❌ 스티커 색으로 버튼을 칠하지 않는다
❌ 두 번째 구조색을 만들지 않는다
```

**⚠️ 단, 운영툴 예외 (결정 필요):**
Notion 마케팅 사이트에는 "에러 빨강"이 없습니다. 하지만 예약 시스템은
**연체 / 취소 / 차단됨** 을 반드시 빨강으로 알려야 안전합니다.

→ 제안: **의미색 4개만 스티커 팔레트에서 차용**하고 문서에 예외로 명시
- 성공/완료 → `#1aae39` (스티커 초록)
- 주의/대기 → `#dd5b00` (스티커 주황)
- 위험/연체 → 빨강 1개 **신규 추가** (Notion에 없어 불가피)
- 정보 → `#0075de` (주요 파랑)

### 2-5. 이관 단계 (위험 낮추는 순서)

| 단계 | 작업 | 범위 | 체감 효과 |
|---|---|---|---|
| **1** | `:root` 토큰 값만 교체 | CSS 약 30줄 | **60%** — 전체 톤이 즉시 바뀜 |
| **2** | 하드코딩 462개 → 토큰으로 치환 | globals.css | 일관성 확보 |
| **3** | 모서리·그림자·타이포 스케일 적용 | 컴포넌트 CSS | Notion 질감 완성 |
| **4** | 표·카드·빈 상태를 Notion 컴포넌트로 | 주요 화면 | 완성 |

## 3. 워크플로우 개선 제안 (핵심)

### 🥇 A. "단체 상황판" (Group Cockpit) — 가장 큰 개선

**문제:** 여행 한 팀 정보가 6개 페이지에 흩어져 있습니다.
견적 보려면 A페이지, 예약은 B, 확정서는 C, 인보이스는 D, 정산은 E, 메시지는 F.
담당자는 하루에도 수십 번 페이지를 옮겨 다닙니다.

**제안:** 투어 코드 하나당 **한 페이지**. 피자 트래커처럼 진행 단계를 보여주고,
**지금 할 일 버튼을 그 자리에** 둡니다.

```
MY-WORLDTRAVE-20260627-A1B2C3   서울&부산 인센티브 · World Travellers · 20명
──────────────────────────────────────────────────────────────
 ①문의 ─ ②견적 ─ ③수락 ─ ④예약 ─ ⑤운영 ─ ⑥확정서 ─ ⑦인보이스 ─ ⑧정산
  ✅     ✅      ✅     ✅     ●현재    ○       ○        ○
──────────────────────────────────────────────────────────────
 [지금 할 일]  운영 업무 3건 중 1건 지연 · 호텔 예약 확인 필요   → [바로가기]
 [파트너 요청] 루밍리스트 업로드 완료 (7/18)                  → [확인]
 [금액]        공개가 5,740,000 · 원가 4,790,000 · 마진 950,000
```

**구현 난이도: 낮음** — `workflow_threads`가 이미 모든 ID를 들고 있어 **새 테이블 불필요**.
기존 `/admin/workflows/[workflowCode]` 페이지를 확장하면 됩니다.

---

### 🥈 B. "오늘 할 일" 대시보드

**문제:** 지금 대시보드는 **숫자판**입니다(견적 수, 미수금 등).
"그래서 내가 지금 뭘 해야 하지?"는 알 수 없어, 담당자가 5개 페이지를 순회하며 찾습니다.

**제안:** 대시보드 최상단에 **한 줄짜리 할 일 목록**을 급한 순서로:

| 우선 | 항목 | 데이터 출처 (이미 존재) |
|---|---|---|
| 🔴 | 기한 지난 운영 업무 | `operation_tasks.due_at < now()` |
| 🔴 | 결제 기한 지난 인보이스 | `invoices.due_date` |
| 🟠 | 승인 대기 공급사 메시지 | `supplier_message_outbox.status='draft'` |
| 🟠 | 미처리 파트너 요청 | `agency_inquiries.status='new'` |
| 🟠 | 실패한 자동화 작업 | `quote_exports`, `supplier_message_outbox='failed'` |
| 🔵 | 읽지 않은 리마인더 | `notifications.status='queued'` |

숫자판은 그 아래로 내립니다. **"보는 대시보드"에서 "일하는 대시보드"로.**

---

### 🥉 C. 네비게이션 평탄화 (숨은 메뉴 없애기)

**문제:** 어드민 상단바에 4개만 보이고 **9개가 "More" 안에 숨어** 있습니다.
매일 쓰는 공급사·확정서·가이드정산이 숨어 있어 2번 클릭해야 합니다.

**제안:** 파트너 포털처럼 **좌측 사이드바 + 그룹**으로 (Notion `ex-app-shell-row` 패턴)

```
📌 업무        오늘 할 일 / 단체 상황판 / 운영 업무
💼 영업        견적 / 파트너사
🚌 운영        예약 / 확정서 / 공급사 / 공급사 메시지
💰 재무        인보이스 / 정산 / 가이드 지출 / 환율
⚙️ 시스템      사용자 / 감사로그 / 자동화
```

전체가 한눈에 보이고, 현재 위치는 Notion 규칙대로 **파란 인디케이터**로 표시.

### D. 전역 검색 (⌘K)

**문제:** 페이지마다 검색창이 따로라, **어느 페이지인지 먼저 알아야** 검색할 수 있습니다.

**제안:** 어디서든 `Ctrl/⌘ + K` → 투어코드·투어명·예약코드·파트너명·인보이스번호를 한 번에 검색.
*(방금 만든 다중 키워드 검색 유틸을 통합 엔드포인트로 확장하면 됨 — 재사용 가능)*

---

### E. 파트너 포털: "내 여행 진행 상황" + 알림

**문제:** 파트너는 견적/예약/인보이스를 **각각 다른 목록**으로만 봅니다.
"내 건이 지금 어디까지 왔는지", "내가 뭘 해야 하는지" 알 수 없고,
새 견적이 와도 **알림이 없어** 직접 들어와 확인해야 합니다.

**제안:**
1. **포털 홈에 진행 바** — 단체별로 `문의→견적→수락→예약→서류→인보이스` 6단계 표시
2. **"당신이 해야 할 일" 박스** — 견적 검토 대기 / 루밍리스트 마감 D-3 / 인보이스 결제 기한
3. **알림 배지** — 새 견적·인보이스 발행 시 표시 (`notifications` 테이블 재사용)

---

### F. 긴 폼 나누기

**문제:** 견적 작성 폼이 **1,787줄 한 화면**입니다(환율표+항목+일정 전부).
처음 쓰는 직원은 어디부터 채워야 할지 압도당합니다.

**제안:** 3단계로 분할 + 자동 임시저장
```
1단계 기본정보(파트너·기간·인원) → 2단계 원가항목 → 3단계 일정·공개요약
```

## 5. 결정이 필요한 사항

1. **폰트** — 어드민 한글에 Pretendard 유지 vs Inter 단독(한글 렌더 저하 감수)?
2. **위험 색상** — Notion에 없는 빨강을 1개 추가하는 것 승인?
3. **네비게이션** — 상단바 유지 vs 사이드바 전환(화면 가로폭 240px 소비)?
4. **범위** — P0 3개만 먼저 vs 전체 순차 진행?
